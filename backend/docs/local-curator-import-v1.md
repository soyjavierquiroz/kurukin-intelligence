# Local Curator Import v1

The separate admin tool at `/admin/research/import/local-curator` is linked from
Admin / Debug. Historical JSONL import remains strict and unchanged.

UTF-8 metadata arrays and native Markdown ID/transcription blocks are joined
only by exact TikTok ID. Stable author ID takes precedence over username.
The importer creates missing global channels/videos, conservatively fills empty
video metadata, and imports missing global transcripts with provenance
`local-curator-import-v1`. Existing transcripts are never overwritten.
Metadata-only videos remain unresolved for transcript acquisition. Transcript
IDs without metadata never create videos. No AI or TikTok requests are made.

SHA-256 covers canonical parsed data, excludes media_file, and is independent
of metadata ordering. Markdown record framing and boundary newlines are excluded;
transcript wording and internal whitespace are preserved. Representative
synthetic fixtures use the supplied example IDs, not the user's transcript text.

## Partial metric observations

Approved additive migration `0011_local_metrics` (parent
`0010_knowledge_strategist`) creates only `video_metric_observations`.
It does not alter videos, snapshots, analyses or transcripts.

Each observation has a video FK with ON DELETE CASCADE, source,
confirmation-time observed_at, nullable views/likes, diagnostic bundle SHA-256,
fingerprint, UUID identity and created_at. Counts must be nonnegative and at
least one count must be known. The index is (video_id, observed_at); uniqueness
is (video_id, source, fingerprint).

Fingerprint is SHA-256 over compact canonical JSON of only known metric keys
and values. It excludes observation time, bundle hash, filenames and media_file.
Unknown values stay null; known zero is distinct from unknown. A repeated
observation is METRIC_UNCHANGED even if unrelated bundle content changes.
Changed counts produce METRIC_NEW_OBSERVATION, retaining the earlier evidence.
The first bundle hash and observation timestamp of reused evidence are retained.

No comments, shares, favorites, rates, outlier scores or ranks are fabricated.
These rows are independent evidence, not scan membership. Existing ranking
queries continue reading VideoSnapshot exclusively: local evidence cannot
change channel median, outlier, priority pool, ranks or scan completeness.

## Publication dates remain required in V1

Video.published_at remains non-nullable. New videos without a valid publication
date are blocked with NEW_VIDEO_MISSING_PUBLISHED_AT; no import-time or other
substitute is used. Existing videos can be reused when incoming dates are absent.
No nullable-publication-date migration is approved or included.

## Preview, confirmation and idempotency

Dry run never persists. It reports detected/new/already-recorded metric
observations as well as asset/transcript coverage and conflicts. Confirmation
uses expiring, single-use, process-local pending data, following the historical
importer. Restarting or routing to another API process requires uploading again.
Confirmation rechecks identity and transcript presence, serializes native imports
with a PostgreSQL advisory transaction lock, and locks existing channels/videos.
Unique constraints guard concurrent scan/import creation; an integrity race
rolls back the whole transaction and requests a fresh preview.

Normal scans reuse global Video by TikTok ID, retain Transcript, avoid unnecessary
acquisition, and create proper VideoSnapshots independently of local evidence.
No analysis, scan snapshot, transcription job or intelligence is generated by
this importer. Re-import creates no duplicate global assets or observations.

## Preview rollout

Build the immutable image from the committed branch HEAD. Verify the image's
source Alembic head is 0011_local_metrics and the production database is at
0010_knowledge_strategist before upgrading. Verify the new table, constraints,
index and database revision before updating only the API. The old API remains
compatible with this additive table. Do not update the worker.

The human uploads metadata.json and transcripciones.md through the preview UI.
Do not search the VPS for those files or automatically confirm the real import.
Stop at the real dry run for human review.
